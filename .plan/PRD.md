# PRD — Bloberry

**One-liner:** A self-hostable, storage-agnostic object service — one API, one SDK and one dashboard over S3, R2, Alibaba OSS, Google Cloud Storage, Azure Blob Storage or plain VPS disk, with real folders, per-folder RBAC, application access keys, and temporary signed links.

**Primary intent:** shared infrastructure for the author's own projects first, with multi-tenancy, per-tenant cost visibility and quota enforcement present from v1 because several projects share one install. Billing is *built* in v1 but left switched off (see G7 and NG5).

---

## Problem

Every application that stores user files rebuilds the same layer, badly. Concretely, across the apps in this repo alone — a portfolio CMS, a laundry-management app, a notes tool, a masjid platform — each one needs file upload, each one needs "make this public", each one needs "don't let tenant A see tenant B's files", and each one currently gets its own half-implementation.

**How this is solved today, and why it falls short:**

| Today's approach                                  | Where it breaks                                                                                                                                                                                                                            |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Call`aws-sdk` directly from the app             | Storage choice is welded into application code. Moving to R2 for egress cost, OSS for a China region, or local disk for an on-prem customer means rewriting and re-testing every upload path in every app.                                 |
| Store the provider URL in the app's own database  | The URL*is* the identity. Move a file, rename a folder, or change provider and every stored reference breaks. There's no stable identifier that survives reorganization.                                                                 |
| Use`/`-separated keys and call it a folder      | Object stores have a flat keyspace. "Rename this folder" is an N-object copy-and-delete; "list this directory" is a prefix scan that gets slower and less correct as the bucket grows.                                                     |
| Bucket-level public/private + a hand-rolled proxy | Granularity stops at the bucket. Giving one application write access to one folder, or letting a tenant member see only their own directory, means an ad-hoc permission table plus a proxy — written fresh, and differently, per project. |
| Reimplement expiring links per project            | Usually without revocation, without an audit trail, and often with the expiry enforced client-side.                                                                                                                                        |
| Nothing at all for operations                     | Once bytes are in a bucket there's no way to browse them, see which client uploaded what, revoke a leaked key, or find the 40 GB of orphaned uploads from a failed migration. The storage bill is the first sign something is wrong.       |

**Who has this problem:** developers and small teams running several products off shared infrastructure (the primary user here); agencies running per-client apps; teams with a self-hosting or data-residency requirement that rules out Uploadthing, Cloudinary or S3-as-a-service.

**Why hosted alternatives don't close it:** Uploadthing and Cloudinary are hosted-only (data leaves your infrastructure, and you inherit their pricing). MinIO is an S3 *implementation*, not an abstraction over other providers, and has no tenant/folder RBAC model. Directus/Supabase Storage bundle storage into a much larger platform you must otherwise adopt. Nothing in that set gives you *one API across six providers* plus folder-level RBAC plus a self-hosted single binary.

## Goals

Each goal states how you'd know later whether it was met.

| #             | Goal                                              | Met when                                                                                                                                                                                                                                                                                          |
| ------------- | ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **G1**  | **One integration, any backend.**           | A tenant is switched from S3 to R2 to local disk from the dashboard, and: no application code changes, no SDK version changes, and every`file_id` issued before the switch still resolves. Verified by an integration test that performs exactly this switch.                                   |
| **G2**  | **The abstraction doesn't leak.**           | All six drivers pass the same conformance suite with zero driver-specific branches in`usecase` or `handler` layers. Grep for driver type names outside `internal/storage/` returns nothing.                                                                                                 |
| **G3**  | **Folders behave like folders.**            | Create/rename/move/delete-subtree/list all work; listing a directory of 10,000 objects returns in**< 200 ms p95** from one indexed query, not a prefix scan; moving a 1,000-object subtree completes in **< 2 s** and issues **zero** object copies in the storage backend.     |
| **G4**  | **Stable identity.**                        | A`file_id` survives folder move, folder rename, object rename, visibility change and storage-backend change. Covered by an explicit test asserting all five.                                                                                                                                    |
| **G5**  | **Permissions are trustworthy and fast.**   | The permission resolver is one pure function with**100% branch coverage** from a table-driven test suite. An authorization check adds **< 5 ms p95** to a request. Revoking an access key takes effect on the **next request** (cache invalidation is explicit, not TTL-based). |
| **G6**  | **Sharing needs no backend of your own.**   | From the dashboard alone, with no code: make an object public, generate a short URL, and issue a signed link with a TTL — and revoke any of the three before expiry.                                                                                                                             |
| **G7**  | **Cost is visible before the invoice is.**  | A platform admin can see, per tenant: bytes stored, object count, bandwidth used, and an**estimated monthly cost** derived from the tenant's storage backend's configured rate card. Estimate is within **±10%** of the provider's own bill for storage and egress.                  |
| **G8**  | **Self-hostable in one command.**           | An operator who has never seen the codebase installs it on a fresh VPS from the documented steps in**under 15 minutes**: one binary, MongoDB, Redis, one Caddy site. The dashboard is served by the same binary — no separate frontend deploy.                                             |
| **G9**  | **Every surface speaks the same contract.** | Go, TypeScript and Dart clients are generated from the committed OpenAPI spec, not hand-written. A breaking API change fails CI on the spec diff before it reaches any client.                                                                                                                    |
| **G10** | **Large files actually work.**              | A 5 GB upload succeeds through the browser (presigned multipart), through the CLI, and through the desktop app, resuming correctly after a deliberate mid-transfer network drop. Bloberry's own memory usage stays**flat** throughout.                                                      |

## Non-goals

Explicitly out of scope, so the plan doesn't quietly grow into them.

| #             | Not doing                                  | Why, and what to do instead                                                                                                                                                                                                                                                                                                                                                                                               |
| ------------- | ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **NG1** | **Not a CDN.**                       | No global PoPs, no edge caching. Put Cloudflare (or the provider's own CDN) in front of a public folder. Bloberry's redirect-to-presigned-URL download path (D1) is specifically designed so this works.                                                                                                                                                                                                                  |
| **NG2** | **Not a media pipeline.**            | No transcoding, image resizing, thumbnailing, OCR, or virus scanning in v1. Archive compress/extract**is** in scope; format conversion is not. Post-v1 candidate N3.                                                                                                                                                                                                                                                |
| **NG3** | **Not Dropbox.**                     | No collaborative editing, document preview/annotation, commenting, or per-file version history beyond what the underlying backend already provides.                                                                                                                                                                                                                                                                       |
| **NG4** | **Not a backup product.**            | No scheduled snapshots, retention policies, or point-in-time restore. Desktop folder sync is one-way convenience and must be described as such in the UI — never as a backup guarantee.                                                                                                                                                                                                                                  |
| **NG5** | **Billing is built but dormant.**    | ⚠️*Revised from "not a billing platform".* Per-tenant **cost estimation and usage metering are v1 Musts** (G7, M18). What is **not** in v1: invoice generation, payment collection, plan/subscription management, dunning, or any payment-provider integration. The data model carries the fields these would need so they can be switched on later without a migration; no UI or API exposes them in v1. |
| **NG6** | **No cross-tenant sharing.**         | A grant lives inside one tenant. Handing a file to an identity outside the tenant is a v2 question (N2).                                                                                                                                                                                                                                                                                                                  |
| **NG7** | **No bulk backend migration in v1.** | Changing a tenant's backend applies to**new** objects; existing objects stay where they are and keep resolving via their recorded backend pointer. Bulk migration is v1.1 (N1). This is why `object` carries its own backend reference rather than inheriting the tenant's current one.                                                                                                                           |
| **NG8** | **No public signup in v1.**          | Tenants and users are created by a platform admin or by invitation. Self-serve registration, email-domain verification and abuse handling are SaaS concerns this install doesn't have yet.                                                                                                                                                                                                                                |
| **NG9** | **Not an S3-compatible API in v1.**  | Bloberry has its own REST API. Accepting`aws-sdk` clients unmodified is attractive (N4) but means implementing S3's XML protocol and signature v4 — a whole second API surface.                                                                                                                                                                                                                                        |

## Requirements

Prioritized, each traced to the stories above. **All six surfaces target v1** — that is the decision, and it is also the plan's largest schedule risk (TRD R9), which is why M13/M9 (contract-first, spec-generated clients) are Musts rather than conveniences.

### Must — v1

| #             | Requirement                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | Stories                     |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------- |
| **M1**  | **Storage driver abstraction** with **six** implementations: S3, Cloudflare R2, Alibaba OSS, Google Cloud Storage, **Azure Blob Storage**, local VPS disk. One interface: put, get, delete, stat, list, presign-get, presign-put, multipart init/part/complete/abort. ## Decisions

Previously open questions, now resolved. Kept here rather than deleted, because the *reasoning* is what a later reader needs.

| #             | Decision                                                                         | Rationale                                                                                                                                                                                                                    | Consequence                                                                                                                                                                                                                                        |
| ------------- | -------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **D1**  | **Private downloads redirect by default; proxy when forced.**              | 302 to a short-lived provider-presigned URL costs near-zero bandwidth and keeps Bloberry out of the data path. Proxying is used only where there's no external signer (local disk) or where a grant requires per-read audit. | Two download paths, both needed regardless — the local-disk driver requires the proxy path anyway. Audit records link*issuance* on the redirect path, not each byte-read; that limitation must be stated in the UI.                             |
| **D2**  | **Folder tree = materialized path + ancestor-ID array.**                   | Mongo makes both natural. The ancestor array is what permission checks and listings actually key off (indexed, ID-based);`path` is a display/lookup convenience.                                                           | A subtree move rewrites descendants'`path` and `ancestors`. Bounded inline; above a threshold it becomes a job (M21). Never a storage-backend copy.                                                                                            |
| **D3**  | **Extraction and bundle generation are queued, never inline.**             | A 2 GB zip cannot be extracted inside an HTTP request.                                                                                                                                                                       | Needs the job system (M21) and status-polling endpoints in v1 — real scope, not an optimization.                                                                                                                                                  |
| **D4**  | **Both install-level credential pool and optional per-tenant BYO bucket.** | Covers the shared-infrastructure shape (the primary use) and the self-hoster shape with one model; the encryption story is identical either way.                                                                             | `storage_backend` records carry an optional `tenant_id`; null means install-level/shared.                                                                                                                                                      |
| **D5**  | **Access keys are bearer tokens, prefixed and hashed at rest.**            | Trivially implementable in three SDKs and in`curl`; HMAC signing is a real tax on SDK adoption and debuggability.                                                                                                          | Leak risk mitigated by scoping, expiry, last-used tracking and instant revoke — all built anyway. Prefix (`blob_live_`) enables secret-scanning. HMAC stays a post-v1 opt-in (N8), so the auth middleware is designed to admit a second scheme. |
| **D6**  | **Short URLs on the main domain at `/s/<slug>`.**                        | One Caddy site, one cert, no extra DNS.                                                                                                                                                                                      | Slugs unique per install, not per tenant. A dedicated short domain can be added later as an alias without a data-model change.                                                                                                                     |
| **D7**  | **Folder grants are allow-only, most-specific-wins. No deny rules.**       | Keeps "who can see this" tractable and the resolver — the highest-risk function in the codebase — exhaustively testable.                                                                                                   | "Access to everything except /private" requires restructuring the tree, not a deny rule. This must be explained in the grant UI, since it will surprise anyone with IAM habits.                                                                    |
| **D8**  | **Dart client is internal to the mobile app in v1.**                       | No pub.dev release surface or API-stability commitment during the period the API moves most, while still dogfooding the contract.                                                                                            | Lives under`mobile/`, not as a separate release target. Promotion to a published package is N6.                                                                                                                                                  |
| **D9**  | **All six surfaces target v1.**                                            | The user's explicit call.                                                                                                                                                                                                    | Accepted as the plan's largest schedule risk (TRD R9). Mitigated structurally: spec-first OpenAPI with generated clients, and desktop reusing the web build verbatim so it isn't a sixth UI.                                                       |
| **D10** | **Billing built, not switched on.**                                        | Cost visibility is needed now (shared infrastructure, several projects); charging anyone is not.                                                                                                                             | Metering and cost estimation are v1 Musts (M18). Invoice/payment/plan fields exist in the model so enabling billing later is a feature flag, not a migration. No billing UI or API in v1.                                                          |
