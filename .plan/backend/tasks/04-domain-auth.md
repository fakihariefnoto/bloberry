# Task group — 04 domain: auth

**Depends on:** `02-migrations`, `03-platform` (httpx, redis, config). **Blocks:** `18-flows.md` (auth flows). Interface names per the Go default: `auth.Repository`, `auth.Usecase`, `auth.Handler` + mockgen-friendly, `var _ auth.Usecase = (*usecase)(nil)`.

- [ ] **`repository.go` / `repository/repository.go`** — User find/create by email, oauth-identity find/link, invitation find-by-token + mark-accepted, membership insert.
- [ ] **`usecase.go` / `usecase/usecase.go`** — the auth business logic (see the six flows in `18-flows.md` for the sequence details); argon2id hashing; the constant-time compare on login.
- [ ] **`handler.go` / `handler/handler.go`** — routes wired to the router: `POST /v1/auth/signup`, `/login`, `/refresh`, `/logout`, `/forgot-password`, `/reset-password`, `/otp/request`, `/otp/verify`, `/google`, **`/pair/issue`, `/pair/verify` (M22), `/config/issue` (M23)**, **`/totp/provision`, `/totp/enable`, `/login/verify-totp`, `/totp/regenerate-backup-codes`, `DELETE /v1/auth/totp` (M24) + the admin `auth.totp_reset`**.
- [ ] **TOTP provisioning (M24, §4.10)** — `totp/provision` generates an RFC-6238 secret (30s, 6 digits), encrypts it at rest with the envelope key (`ERD.md` users.totp), returns the `otpauth_url` + secret **exactly once**; `totp/enable` requires a confirming code before activating (MV-E5) and mints **10 backup codes** (argon2id-hashed, single-use). Regeneration invalidates the old set. Disable requires a current code or an unused backup code.
- [ ] **TOTP verify on every human login (M24, §4.10)** — password/OTP/Google primary factor succeeds → if `totp.enabled`, return `totp_required` with **no session issued** → `login/verify-totp` checks a TOTP code (current ±1 window) or a single-use backup code, then issues the session. The `totp:pending:<user_id>` Redis key bridges the two steps (5m, attempt-capped per pending token).
- [ ] **Admin TOTP reset** — the platform-admin recovery path (R15): a documented, audited (`auth.totp_reset`) admin action that disables a locked-out user's 2FA — never self-serve, never email-based.
- [ ] **QR pairing (M22, §4.8)** — `pair/issue` mints a one-time Redis token (2m TTL) from an authenticated session, returns a `bloberry://pair/<token>` payload; `pair/verify` exchanges it for a mobile-TTL session, **DELs the token on use** (single-use), **rate-limits per token**, audits `auth.pair`. A used/expired token → `pair_invalid` ("This code is no longer valid — refresh it").
- [ ] **Config-file issue (M23, §4.9)** — `config/issue` mints a refresh token for the platform + a **server-signed payload** carrying an **import-window claim (+24h)**; returns the signed (not yet encrypted) payload. The web client encrypts client-side; the server never sees the passphrase. The resulting session is an ordinary revocable refresh token (DT-E2). Audits `auth.config_export`.
- [ ] **JWT issuance** — HS256 pinned (`jwt.WithValidMethods([]string{"HS256"})` + keyfunc asserts `*jwt.SigningMethodHMAC`; no `alg:none` anywhere, including tests), platform-aware TTLs (web access 48h/refresh 144h; mobile 720h/2160h), `platform` from the client defaulting to mobile.
- [ ] **Redis refresh-token store** — opaque refresh tokens, **rotation on every refresh** (old token deleted; presented twice fails), per `domains.md` §4.3.
- [ ] **Rate limiting on OTP + password reset** — per-email attempt caps and cooldowns (`otp:attempts:` counter, reset `SETEX`), per `domains.md` §4.4/4.5.
- [ ] **Invitation acceptance** — existing-email adds a membership rather than erroring (`domains.md` §4.1); new user created with `email_verified:false` + verification email.
- [ ] **Google login** — id_token verification (signature/aud/iss/exp), auto-link only when Google asserts the email is verified (no account-takeover path, §4.6), `no_invitation` for a valid identity with no account (NG8).
- [ ] **Logout revokes server-side** — deletes the Redis refresh session, not just "forgets" it.

**tests:** constant-time login (identical response + timing for unknown-email vs wrong-password); refresh rotation (second use of a rotated token fails); JWT alg pinning (a token with `alg:none` is rejected); OTP attempt cap + rate limit; Google email-unverified does not auto-link; **pair token is single-use (a second verify fails) + expires in ~2m + rate-limited; config payload is signed (tamper → `config_invalid`) + the import window rejects past 24h; TOTP secret shown once + confirm-before-enable; `totp_required` issues no session; TOTP valid / backup-code-valid / neither paths; a used backup code can't be reused; admin reset is audited and never self-serve**.
