# Design system — Bloberry

Single source of truth for colors, typography, spacing, shape, elevation, motion, and component specs. Both `mobile/mockup/` (Flutter) and `web/mockup/` (Vue) screens reference this file instead of restating values — a screen file only documents what's *different* for that screen. The Wails desktop shell reuses the **web** build verbatim, so it inherits this file with no deltas beyond native chrome.

**UI kits** — web/desktop: **Reka UI** (unstyled headless primitives, styled into the app's own Tailwind components). Mobile: **shadcn/ui for Flutter**. Both are styled entirely by the tokens in this file — neither ships a competing default theme, which is why the two surfaces stay visually one product. Icons: **Lucide** on every platform.

**Direction:** blueberry indigo, restrained. Bloberry is infrastructure people trust with their files — the UI should read as calm, dense and legible, not as a marketing site. Color carries state and action; everything else is neutral. No gradients or glassmorphism in the product interior (the landing page may use them, recorded there if so).

Colour generated by `node design-collection/palettes/generate-palette.mjs "#8B7DEB"`. Type and spacing from `node design-collection/scales/generate-scale.mjs` (base 14, ratio 1.2). Shape language: **Soft** throughout (radius, elevation, motion) — one language, not mixed.

## Colors

| Token | Light | Dark | Usage |
|-------|-------|------|-------|
| `color.background` | `#F9F9FB` | `#17161D` | Screen/page background |
| `color.surface` | `#EDEDF3` | `#23212B` | Cards, inputs, table headers, sidebar |
| `color.surface-raised` | `#FFFFFF` | `#2C2A36` | Modals, dropdowns, popovers — one step above `surface` |
| `color.border` | `#D4D4E3` | `#3A3749` | Dividers, outlines, table rules |
| `color.text` | `#17171C` | `#F1F1F4` | Body text |
| `color.text-muted` | `#5C5C70` | `#9F9DAF` | Secondary text, timestamps, byte counts, breadcrumbs |
| `color.primary` | `#3A22DD` | `#8B7DEB` | Primary actions, brand, active nav, links |
| `color.on-primary` | `#FFFFFF` | `#17161D` | Text/icons **on** `color.primary` — **see the caveat below, the two modes differ** |
| `color.primary-subtle` | `#E7E3FB` | `#2A2540` | Selected row, active tab background, tag fill |
| `color.accent` | `#3A22DD` | `#8B7DEB` | Same as primary — this is a single-hue system by design |
| `color.error` | `#C52B20` | `#E46258` | Errors, destructive actions, over-quota |
| `color.success` | `#1F7A40` | `#47D17A` | Upload complete, key active, healthy backend |
| `color.warning` | `#8A5300` | `#E8A33D` | Nearing quota, key expiring soon, pending job |
| `color.disabled` | `#D4D4E3` | `#3A3749` | Disabled control background |
| `color.on-disabled` | `#8A8A9C` | `#6C6A7C` | Disabled control label |

**Contrast caveats — these are constraints, not footnotes:**

- **Primary buttons need different labels per mode.** Light: `#FFFFFF` on `#3A22DD` = **8.56:1** ✅. Dark: white on `#8B7DEB` is only **3.37:1** ❌ for normal text — dark mode primary buttons use `color.on-primary` = `#17161D`, which is **5.37:1** ✅. Never hardcode a white button label.
- Every other pair passes WCAG AA at normal text size: text on background 16.99:1 (light) / 15.94:1 (dark); text-muted 6.20 / 6.77; primary as text/link on background 8.14 / 5.33; error 5.34 / 5.29; success 5.10 / 9.13.
- `color.primary-subtle` is a fill only — never put `color.text-muted` on it. Selected-row text stays `color.text`.

**Semantic mapping for storage state** (used across the file browser, key list and backend list — define once, not per screen):

| State | Color | Where |
|---|---|---|
| Public object | `color.warning` | Globe badge on a file row — public is a *caution*, not a success |
| Private object | `color.text-muted` | Lock icon, no emphasis (it's the default) |
| Active / healthy | `color.success` | Key active, backend reachable, upload complete |
| Expiring / pending | `color.warning` | Key expiring < 7 days, extraction job queued, quota > 80% |
| Revoked / failed / over quota | `color.error` | Revoked key, failed upload, unreachable backend, quota exceeded |

## Typography

One scale, every size on it. A screen needing "something between body and heading-md" means adding a token here, not inventing an off-scale size inline.

| Token | Size / Weight / Line-height | Usage |
|-------|------------------------------|-------|
| `text.display` | 29 / bold / 36 | Empty-state headline, usage hero numbers, splash |
| `text.heading-lg` | 24 / bold / 32 | Page titles ("Files", "Access keys") |
| `text.heading-md` | 20 / semibold / 28 | Section headings, modal titles |
| `text.heading-sm` | 17 / semibold / 24 | Card titles, list-item titles, folder names in the tree |
| `text.body` | 14 / regular / 20 | Body copy, file names, table cells |
| `text.body-strong` | 14 / semibold / 20 | Emphasis, key values, active breadcrumb segment |
| `text.button` | 14 / semibold / 20 | Button labels, all sizes |
| `text.label` | 12 / medium / 20 | Form labels, tabs, chips, table column headers |
| `text.caption` | 12 / regular / 20 | Timestamps, byte counts, hints, help text |
| `text.mono` | 13 / regular / 20 | **Bloberry-specific.** `file_id`s, access keys, storage paths, CLI snippets, SDK code samples, short-URL slugs |

Generator output verified: every step visibly distinct, all line-heights on the 4px grid, body/caption above minimum size.

**Font family**
- Web + desktop: **Inter** (variable), fallback `system-ui, -apple-system, "Segoe UI", sans-serif`.
- Mobile: system default — SF Pro (iOS) / Roboto (Android). Don't ship Inter to mobile just for parity; the system face reads better at small sizes on device.
- Monospace (all platforms): **JetBrains Mono**, fallback `ui-monospace, SFMono-Regular, "Cascadia Mono", monospace`.

`text.mono` exists because Bloberry displays a lot of machine strings — an ID or key rendered in a proportional face is genuinely harder to compare and to transcribe. Use it for anything the user might copy, and always pair it with a copy button.

## Spacing

| Token | Value |
|-------|-------|
| `space.xs` | 4px |
| `space.sm` | 8px |
| `space.md` | 16px |
| `space.lg` | 24px |
| `space.xl` | 32px |
| `space.2xl` | 48px |

Mobile screen padding: `space.md`. Web page padding: `space.lg` (desktop) / `space.md` (mobile). Gap between stacked cards: `space.sm`. Gap between page sections: `space.lg`. **File-table row padding: `space.sm` vertical** — this is a data-dense surface; `space.md` rows waste a third of the viewport.

## Shape (border radius)

| Token | Value | Applied to |
|-------|-------|------------|
| `radius.sm` | 8px | Chips, badges, tags, permission pills |
| `radius.md` | 12px | Buttons, inputs, small cards, dropzone |
| `radius.lg` | 20px | Cards, sheets, modals |
| `radius.full` | 9999px | Avatars, status pills, FAB |

`design-collection/scales/curated-scales.md` → Radius, **Soft** language. One radius per component type, never varied per screen.

## Elevation

| Token | Shadow | Applied to |
|-------|--------|------------|
| `elevation.none` | none — `1px` `color.border` outline instead | **Default.** Cards, panels, the file table, the folder tree |
| `elevation.sm` | `0 1px 3px rgba(0,0,0,0.10)` | Dropdowns, context menus, raised cards |
| `elevation.md` | `0 4px 12px rgba(0,0,0,0.12)` | Modals, sheets, popovers, the upload-queue panel |
| `elevation.lg` | `0 8px 32px rgba(0,0,0,0.16)` | Confirmation dialogs (delete folder, revoke key), FAB |

**Soft** language, same as Radius and Motion. Border-only is the default — a flat panel with a crisp border reads cleaner in a dense admin UI and stays legible in dark mode. In dark mode, don't raise shadow opacity to compensate; lean on `color.surface` sitting lighter than `color.background`, and use `color.surface-raised` for anything that genuinely floats.

## Sizing & touch targets

| Token | Value | Notes |
|-------|-------|-------|
| `size.touch-min` | 48×48dp (mobile) / 40×40px (web) | **Minimum** hit area for anything tappable, even when the visual is smaller. Expand the hit area, don't inflate the icon. |
| `size.button-height` | 48px | Primary/secondary buttons |
| `size.button-height-sm` | 36px | Compact/inline only — file-row actions, table toolbars. **Below the touch minimum**; pointer-first surfaces only, never the sole action on a mobile screen. |
| `size.input-height` | 48px | Text fields, selects |
| `size.icon` | 24px | Standard icon |
| `size.icon-sm` | 20px | Leading icons inside inputs, file-type icons in table rows |
| `size.avatar` | 40px | List/nav avatars, member rows |
| `size.appbar-height` | 56px | Mobile top app bar |
| `size.navbar-height` | 64px | Mobile bottom tab bar |
| `size.sidebar-width` | 260px | Web sidebar, expanded |
| `size.navrail-width` | 72px | Web nav rail, collapsed |
| `size.tree-width` | 280px | **Bloberry-specific.** Folder tree inside the **move-picker dialog** — not a browser pane; see the Folder tree component note |
| `size.row-height` | 44px | **Bloberry-specific.** File-table row — dense but still above the 40px web touch minimum |

Accessibility-derived, not stylistic (48dp satisfies both Material's 48dp and Apple's 44pt).

**Icon set: Lucide**, on every platform (`lucide-vue-next` on web/desktop, `lucide_icons` on Flutter). One set only. Bloberry needs a consistent file-type icon mapping — define it once in `web/components.md` and mirror it in mobile.

## Motion

| Token | Duration / Easing | Usage |
|-------|--------------------|-------|
| `motion.fast` | 150ms / ease-out | Hover, press, toggle, tooltip, row selection |
| `motion.base` | 250ms / ease-in-out | Expand/collapse folder node, fade, snackbar, upload-panel slide |
| `motion.slow` | 400ms / ease-in-out | Route transitions, sheets, modals |

**Soft** language. Respect the OS "reduce motion" setting with an **instant** state change, not a shortened animation.

**Progress is not decoration.** Upload/extraction progress bars animate at the real rate of the underlying operation — never a fake indeterminate crawl. An upload that has stalled must visibly stall, because a user watching a fake bar can't tell a slow upload from a dead one.

## Components

Every component needs a spec precise enough to build without guessing, **including its states**. Disabled is not optional — the UX guard rules in `templates/flutter-defaults.md` require controls to be disabled while an async action is in flight.

### Button — primary
- Background `color.primary`, label `color.on-primary` (`text.button`), `radius.md`, height `size.button-height`, horizontal padding `space.md`.
- **Light mode label is `#FFFFFF`; dark mode label is `#17161D`.** See the contrast caveat above.
- **Pressed**: 90% opacity. **Disabled**: `color.disabled` background, `color.on-disabled` label, no shadow, cursor `not-allowed`. **Loading**: spinner replaces the label, width held constant so the button doesn't resize, control non-interactive.
- **Focus** (web/keyboard): 2px `color.primary` outline, 2px offset.

### Button — secondary
- Transparent background, `1px` `color.primary` border, label `color.primary`. Same height/radius/padding and same four states.

### Button — destructive
- Background `color.error`, label `#FFFFFF` (light) / `#17161D` (dark, same reasoning as primary). Used for delete folder, revoke key, remove member.
- **Always paired with a confirmation dialog** that requires typing the resource name for irreversible subtree deletes and key revocations. Never a bare one-click destroy.

### Button — ghost / icon
- Transparent, label/icon `color.text-muted`, hover background `color.surface`, `radius.md`, `size.button-height-sm` for inline table actions. Hit area still `size.touch-min`.

### Input / text field
- Background `color.surface`, `1px` `color.border`, `radius.md`, height `size.input-height`, padding `space.sm`/`space.md`.
- Label above in `text.label`; helper/error text below in `text.caption`.
- **Focus**: border `color.primary` (2px). **Error**: border `color.error`, message below in `color.error`. **Disabled**: `color.disabled` background, `color.on-disabled` text.

### Card / panel
- Background `color.surface`, `radius.lg`, padding `space.md`, `elevation.none` (border) by default.

### Data table (file browser, keys, members, audit)
- Header row: `color.surface`, `text.label` in `color.text-muted`, `1px` bottom `color.border`, sticky on scroll.
- Row height `size.row-height`, `1px` bottom `color.border`, `text.body`.
- **Hover**: background `color.surface`. **Selected**: background `color.primary-subtle`, text stays `color.text`, `2px` left bar in `color.primary`.
- Row actions appear on hover (pointer) / are always visible in an overflow menu (touch) — never hover-only as the sole path.
- **Loading**: skeleton rows at `size.row-height`, not a centered spinner. **Empty**: see Empty state. **Error**: inline banner above the table with a retry action, table area left blank rather than showing stale rows.

### Folder tree — **move-picker dialog only**
> **Scope note.** The file browser is breadcrumbs + table with **no persistent tree pane** (decided in `detail-web`; see `web/navigation.md`). This component and `size.tree-width` survive for exactly one surface: the **move-picker dialog**, where you must see the destination hierarchy to choose a target. Don't reintroduce it as a pane without revisiting that decision.

- Width `size.tree-width` (within the dialog), background `color.surface`, indent `space.md` per level, node height `size.row-height`.
- Node: chevron (`size.icon-sm`, rotates at `motion.fast`), folder icon, name in `text.body`.
- **Active node**: `color.primary-subtle` background, name in `text.body-strong`. **Drop target** (drag-over): `2px` dashed `color.primary` outline, `color.primary-subtle` fill.
- **Loading children**: two skeleton nodes at the child indent. **Empty folder**: no children rendered, chevron hidden.

### Dropzone
- `2px` dashed `color.border`, `radius.md`, background `color.background`, centered upload icon (`size.icon`) + `text.body` prompt + `text.caption` constraint line ("Max 5 GB per file").
- **Drag-over**: border and icon `color.primary`, background `color.primary-subtle`, `motion.fast`. **Rejected type/size**: border `color.error`, message in `color.error`, reverts after 3s.

### Upload queue panel
- Bottom-right docked panel, `color.surface-raised`, `radius.lg`, `elevation.md`, collapsible header showing "N uploading · M done".
- Per item: file-type icon, name (truncated middle, never the extension), determinate progress bar in `color.primary`, byte-count + rate in `text.caption`.
- **Complete**: check in `color.success`. **Failed**: `color.error` with a retry button and the real reason. **Paused/stalled**: `color.warning` — a stalled upload must look stalled.

### Status pill
- `radius.full`, `text.label`, padding `space.xs`/`space.sm`, tinted fill from the semantic mapping above with the matching text color. Used for key state (active/expiring/revoked), backend health, job status, object visibility.

### Code / secret display
- `text.mono` on `color.surface`, `radius.sm`, padding `space.sm`, with a copy button.
- **A newly issued access key is shown exactly once**, in a modal, with an explicit "you won't see this again" line in `color.warning` and a copy button that confirms. Everywhere else the key is masked (`blob_live_••••4f2a`) with only the last 4 characters shown. Never render a full secret in a table.

### Nav
- **Web/desktop**: left sidebar `size.sidebar-width`, background `color.surface`, collapsing to `size.navrail-width`. Active item: `color.primary-subtle` fill, icon and label `color.primary`, `text.body-strong`. Inactive: `color.text-muted`.
- **Mobile**: bottom tab bar, height `size.navbar-height`, icons `size.icon`, active tint `color.primary`, inactive `color.text-muted`, label `text.caption`.
- **Breadcrumbs** (file browser): `text.body` in `color.text-muted`, `/` separators, final segment `text.body-strong` in `color.text`. Collapses to `Root / … / Parent / Current` beyond 4 levels, with the ellipsis opening a dropdown of the elided segments.

### Feedback
- **Snackbar/toast**: `color.surface-raised`, `radius.md`, `elevation.md`, `motion.base` entry, auto-dismiss ~4s. Errors use `color.error` for the icon/accent stripe, not the whole background. Destructive actions get an **Undo** affordance where the operation is reversible (move, soft delete) and none where it isn't (key revoke) — the absence is the signal.
- **Empty state**: Lucide icon at 48px in `color.text-muted`, `text.heading-sm` headline, `text.body` in `color.text-muted`, and an action button when there's something to do. Bloberry has several distinct empties — empty folder, no search results, no access keys yet, no audit events in range — and they must say different things. "No files here yet · Drag files in or press Upload" is useful; "No data" is not.
- **Skeleton loader**: `color.surface` blocks at the real content's dimensions, subtle pulse at `motion.base`. Used for table/tree/detail first-loads instead of a centered spinner.
- **Permission-denied state**: not an error toast. Render the surface with the blocked action visibly disabled and a `text.caption` line naming what's needed ("Requires `write` on this folder"). A viewer should understand the boundary, not hit a wall.

Keep app-specific shared components consistent with `web/components.md` as they're defined.

## Notes

Update this file as decisions are made; don't let mobile and web drift. A one-off exception goes in that screen's own `.md` file — and if the same exception shows up on a third screen, it isn't an exception, promote it here.

Two things this file deliberately decides once because Bloberry would otherwise get them wrong per-screen: **`color.on-primary` differs between light and dark mode**, and **public visibility is a warning color, not a success color**.
