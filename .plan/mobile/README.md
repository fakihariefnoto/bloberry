# Mobile — Bloberry

**Flutter.** App identifier: **`com.bloberry.app`** — this exact string on both Android (`applicationId` in `android/app/build.gradle`) and iOS (`PRODUCT_BUNDLE_IDENTIFIER` / `CFBundleIdentifier`).

Mobile is the **capture-and-check** surface, not a second dashboard: get files off a phone into a folder, browse and share what's there, and let a tenant admin handle something urgent (revoke a leaked key, check quota) without a laptop. Administrative depth stays on web.

Follows [`templates/flutter-defaults.md`](../../../templates/flutter-defaults.md). Route graph: [`navigation.md`](navigation.md). Design tokens: [`../design/style-guide.md`](../design/style-guide.md) — shared with web, except mobile uses the **system font** (SF Pro / Roboto), not Inter.

**[shadcn/ui for Flutter](https://github.com/nank1ro/flutter-shadcn-ui)** — a composable, style-agnostic kit whose components are driven entirely by the shared tokens from `design/style-guide.md`. ## JSON field casing — the one that silently breaks

The Go backend emits **snake_case** on every field. Dart's `json_serializable` defaults to camelCase and does **not error** on a mismatch — it deserializes every field to `null`. A model that looks correct produces empty screens with no exception anywhere.

Configure it globally in `build.yaml` rather than annotating each class:

```yaml
targets:
  $default:
    builders:
      json_serializable:
        options:
          field_rename: snake
```

This is the first thing to verify when wiring the API client, before any screen is built.

## UX guard rules — what they mean here

The five rules from `templates/flutter-defaults.md`, made concrete for this app:

1. **Loading state** — `files` uses skeleton rows at `size.row-height`, not a centered spinner (`design/style-guide.md`). First load of a large folder is the common case.
2. **Disabled while processing** — Share, Move, Delete and Revoke all disable and show a spinner in place of their label, width held constant.
3. **Overflow-safe** — file names are long and arbitrary. Middle-truncate preserving the extension (`quarterly-report-final-v3.pdf` → `quarterly-rep…v3.pdf`), never end-truncate, which hides the one part that identifies the type. Test with a 200-character filename.
4. **Envelope, never raw** — parse `{data?, messages?}` in one Dio interceptor. `messages[].code` drives branching (`key_revoked` → re-login, `quota_exceeded` → link to `usage`); `messages[].content` is the snackbar text. Dio exceptions and stack traces are logged via `debugPrint`, never shown.
5. **Biometric unlock** — optional Settings toggle, off by default. On Android this **requires `MainActivity` to extend `FlutterFragmentActivity`**, not `FlutterActivity`, or the prompt crashes at runtime. Its failure path is logged, not swallowed.

## The upload queue is the real engineering

Everything else on mobile is a list and a form. The queue is where the work is (PRD MB2, G10; `architecture.md` §3.7):

- **Persisted in SQLite**, not memory — must survive app kill, not just backgrounding.
- **Multipart with per-part tracking.** On resume, reconcile against `GET /v1/objects/:id/multipart/status` and re-send only missing parts. Trusting the local record alone re-uploads parts the server already has; trusting the server alone loses the local-file mapping. Both are needed.
- **Real progress.** A stalled upload must visibly stall (`design/style-guide.md`) — a fake indeterminate bar makes a dead upload look identical to a slow one.
- **Bytes go straight to the provider** via presigned URLs; only `init` and `complete` touch Bloberry. So a queued upload survives session expiry, and only its `complete` waits for re-login.
- **Foreground service on Android** while uploads are in flight, or the OS kills them. iOS gets a background processing task, which is best-effort by design — say so in the UI rather than promising more than the platform gives.

## Form validation

One `lib/validators.dart` — email, password strength, folder name (no `/`, no leading dot, length cap), TTL range. Never duplicated per screen. No phone-number input anywhere in this app, so no dial-code package is needed.

---

## The Dart SDK question

PRD **D8**: the Dart client is **internal to this app in v1** — it lives at `mobile/lib/api/`, generated from `api/openapi.yaml` (`architecture.md` §7), and is not published to pub.dev. That avoids an API-stability commitment during the period the contract moves most. Promotion to a published package is PRD N6.
