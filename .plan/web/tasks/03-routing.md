**Source:** `web/navigation.md` — the authoritative route graph. Route table rows below come from it verbatim; the shell layout from its Shell section; flow chains from its §Flow chains (the chains themselves are built in `33-flows.md`; this file owns the *plumbing*).

- [ ] **Navigation shell (`AppShell`)** from `web/navigation.md` §Shell: left sidebar `size.sidebar-width` 260px, section groups WORKSPACE (Files, Shares, Jobs) / ADMINISTRATION (Applications, Members, Audit log, Usage, Settings) / PLATFORM (Tenants, Storage backends, Install usage), tenant switcher pinned top, user menu pinned bottom. Role-driven section visibility: ADMINISTRATION hidden for member/viewer, PLATFORM for everyone but platform_admin — **hidden ≠ protected**, every route independently guarded server-side too.
- [ ] **Collapse behavior.** Sidebar collapses to `size.navrail-width` 72px below ~1200px; becomes a drawer behind a hamburger under 768px. **No bottom tab bar on web** (it's an admin surface). Persists collapse state per user (via `stores/ui`).
- [ ] **Auth gating per route**, from the route table's Auth column: public (`login`, `otp-login`, `forgot-password`, `reset-password`, `accept-invitation`, `link-expired`, `not-found`); any-authenticated (`files`, `file-detail`, `shares`, `jobs`, `profile`, `account-settings`, `pair-device`, `forbidden`, `tenant-suspended`); tenant_admin+ (`applications`, `application-detail`, `members`, `audit`, `usage`); tenant_owner only (`tenant-settings`); platform_admin only (the five admin routes).
- [ ] **Unauthenticated redirect with `?next=`.** Any guarded route hit without a session → `login?next=<path>` → return there after login. Losing the destination on session expiry is a small thing that feels broken every time.
- [ ] **401 handling.** Any authenticated request returning 401 → redirect to `login?next=<current>`. (The token-refresh mechanics live in `05-core-infra.md`; this is the route-level reaction.)
- [ ] **403 handling.** A guarded route rejected server-side → `forbidden`, which renders the explanation (mockup `forbidden.md`) naming what's needed.
- [ ] **Tenant-suspended guard.** Any authenticated request while the tenant is suspended → `tenant-suspended`, before the page renders its own failure.
- [ ] **Route transitions.** `motion.slow` fade between routes; reduced-motion users get instant swaps.
- [ ] **Scroll restoration** to top on route change (except `files` breadcrumb navigation, which should restore where sensible).

**tests:** a routing test asserting each route's auth gate (public vs authenticated vs role), the `?next` round-trip, and the catch-all → `not-found`; the 401 → login redirect with destination preserved.
