# Task group — 05 core infra

**Depends on:** `01-setup.md` (deps), `04-environments.md` (API base). **Blocks:** every data-dependent page and the auth pages' submit paths. Shared HTTP/state plumbing — the pages that follow must never each invent error handling or field mapping.

**Source:** `web/components.md` §Data layer, `templates/web-defaults.md` (envelope + snake_case), `backend/domains.md` (auth flows, error codes).

- [ ] **`lib/api/` — generated client.** Client code generated from `api/openapi.yaml` (ADR-11, spec-first), not hand-written. Regenerated by `make generate`; CI fails if the working tree changes (keeps spec-first honest). This is the only place API types live.
- [ ] **`lib/envelope.ts` — the one envelope parser.** Unwraps `{data?, messages?: [{code, content}]}`. Surfaces `messages[].content` via the Toast component on success **and** error (`messages` isn't error-only). Branches on `messages[].code` for client-side logic (field-specific form errors, re-auth on `refresh_invalid`, terminal no-retry on `key_revoked`/`key_expired`). **Never surfaces raw provider or exception text** — one place, so 26 pages can't each invent error handling.
- [ ] **snake_case → camelCase decided and applied once** (`templates/web-defaults.md`): transform at the HTTP-client boundary (recursive key-mapper or `camelcase-keys`), or type interfaces in snake_case to match the wire exactly. Either is fine — the point is one decision in one layer, never per call site.
- [ ] **HTTP client layer** wrapping the generated `lib/api/`: attaches the auth header, handles 401 → refresh-token round-trip (platform-aware TTLs, `backend/domains.md` §7) then retries the original request once; on refresh failure → route-level 401 handling in `03-routing.md` fires.
- [ ] **Runtime API-base override for desktop.** `lib/api/` reads `window.__BLOBERRY_API_BASE__` when present, falls back to the build-time `VITE_API_BASE_URL` (`web/components.md` §Environments — the desktop shell loads the same bundle against a user-configured server URL).
- [ ] **`stores/` (Pinia).** `auth` (session, principal, role, token), `tenant` (current tenant, switcher — switching **always lands on `files` at the new root**), `upload` (the queue — survives navigation, which is why it's a store and not component state), `ui` (sidebar collapse, table density).
- [ ] **`lib/permissions.ts`.** Client-side mirror of the resolver's *shape* for enabling/disabling UI — advisory only, server is the authority. The file itself states this (a client-side permission helper is exactly what someone later mistakes for enforcement).
- [ ] **Form validators centralized** (`templates/web-defaults.md` / backend defaults): email/password/phone regexes in one module, imported by `FormField`-based forms — never redefined per page.
- [ ] **i18n keys vs literal strings.** `messages[].code` → i18n key mapping lives in `envelope.ts`; user-visible copy for known codes is centralized here so the same backend error reads the same on every page.

**tests:** envelope-parsing unit tests (success data, success-with-messages, error-messages, unknown-code fallback); snake_case transform round-trip; auth-refresh-then-retry test (401 → refresh → original request retried once); the `key_revoked` terminal no-retry branch.
